# KSP 迁移前的源域敏感性检查

在同一批 100 个源域验证起点上，冻结 online 策略将推力提高到候选船水平后仍全部安全入靶。单独削弱姿控时，其安全数从惯量 ×2 时的 98 降到 ×2.5 时的 94。纯克隆可承受更弱的姿控，但在全推代理下 100 次均超时。保留实船姿控还是调整飞船，取决于实测可用力矩及拟迁移的控制器。以下为源域验证结果。

## 事前登记与方法

2026-11-26，在看到任何 KSP 策略评估结果之前，登记三名零样本候选及选优顺序。在相同 KSP 起点上分别运行发布策略 `online`、同种子的行为克隆 `bc_only` 和只知道 pilot 参数的 `scripted_nominal`，完整报告三者。先比较安全率，再比较安全且入靶率，最后比较原始平均回报。三项相同则报告并列。`scripted_privileged` 读取扰动后的物理参数，只用于判断在新动力学下能否产生克隆示范。[S3 选优记录](../../docs/validation.md#frozen-comparison-on-100-starts-per-split)

本次源域检查使用种子 33 第 22 轮的冻结策略、同一训练种子的纯克隆检查点，以及 Release 中 100 个固定验证起点。每个条件都从相同起点重置控制器和模拟器。坠毁、超时等失败均计入分母。报告中“安全入靶”要求安全并且**首次触地**落点距目标不超过 5 m。扰动只改动力学、动作执行时刻或控制器看到的观测，不重新拟合世界模型或控制器。[冻结策略与清单](S3_HANDOFF.md) · [名义模拟器参数](../../simulator/configs/nominal.json)

全轴惯量倍数为 k 时，pilot 三轴单位满输入的静止角加速度为 (0.75, 0.75, 0.50)/k rad/s²。在实测网格上分别找安全数至少 95 的最大倍数、低于 95 的最小倍数。这个实验只界定已测网格上的边界。下文的“95/100”指点计数，汇总表另列 Wilson 95% 置信区间。KSP 力矩估算采用测试构型中 KSP 船体 +Y 对应任务 +Z 的假设。按任务俯仰、偏航、滚转顺序，用 I = (18,760.8 / 18,052.6 / 20,964.0) kg·m²，计算 `τ[kN·m] = I × α / 1000`。每个数表示对应单轴可用力矩的大小，正反向、轴间耦合和实际控制输入的符号仍待脉冲标定。[测试机体系映射](https://github.com/Aurora-on/KSP/blob/01aac917/configs/ksp_mun_test.toml) · [候选飞船测量](https://github.com/Aurora-on/KSP/blob/01aac917/docs/validation.md#L44-L58)

分轴诊断将俯仰、偏航惯量同时放大 4 倍。只把滚转惯量从 800 放大到 3,200 kg·m² 会超过其余两轴惯量之和 2,400 kg·m²，模拟器按刚体三角不等式拒绝该配置。因此分别只把滚转惯量放大到合法边界 3 倍，以及保持惯量不变、仅将滚转力矩减至 1/4。后者复现指定的纯滚转初始角加速度，转动中的轴间耦合仍与改惯量不同。[刚体参数校验](../../simulator/src/mun_lander/config.py)

候选船的四台发动机报告最大真空推力合计 240 kN，湿质量为 11,460 kg。以 pilot 湿态 9 kN / 1,800 kg = 5 m/s² 为基准，全推和 25% 限推的推重能力倍数分别为 4.1885 和 1.0471。试验仅缩放 pilot 推力，其他参数按各条件指定。`delay1` 在第一步执行全零动作，以后将四通道动作整体推迟一个控制周期（0.1 s）。这比 KSP 记录到的一帧油门响应滞后（0.02 s）长五倍，也涵盖了三个 RCS 通道，只用于考察悲观情形。旧脉冲外推的约 0.07 rad/s² 仅用于设定弱姿控端点。统一放大惯量约 10.71 倍时，实际测试的俯仰、偏航、滚转能力分别是 0.070、0.070、0.0467 rad/s²。[推力与脉冲记录](https://github.com/Aurora-on/KSP/blob/01aac917/docs/validation.md#L769-L778)

## 姿控能力与安全门槛

下表按俯仰 / 偏航 / 滚转列三轴数值。每种控制器各列出最后一个达标的网格点和第一个低于 95/100 的网格点。力矩是按候选船惯量换算的需求估计，实际可用力矩仍需适配组验证。

| 控制器 | 网格点 | 惯量倍数 | 安全 / 100 | 满输入角加速度（rad/s²） | 对应力矩（kN·m） |
|---|---|---:|---:|---|---|
| online | 最大达标 | 2 | 98 | 0.375 / 0.375 / 0.250 | 7.04 / 6.77 / 5.24 |
| online | 最小未达标 | 2.5 | 94 | 0.300 / 0.300 / 0.200 | 5.63 / 5.42 / 4.19 |
| bc_only | 最大达标 | 3 | 97 | 0.250 / 0.250 / 0.167 | 4.69 / 4.51 / 3.49 |
| bc_only | 最小未达标 | 4 | 79 | 0.188 / 0.188 / 0.125 | 3.52 / 3.38 / 2.62 |
| scripted_privileged | 最大达标 | 6 | 95 | 0.125 / 0.125 / 0.0833 | 2.35 / 2.26 / 1.75 |
| scripted_privileged | 最小未达标 | 10.714 | 0 | 0.070 / 0.070 / 0.0467 | 1.31 / 1.26 / 0.98 |

**本组起点的主要敏感轴是俯仰/偏航。** 全轴惯量 ×4 与仅俯仰/偏航 ×4 对每个起点都给出相同的终局类别与安全入靶标志。按 online、bc_only、scripted_nominal、scripted_privileged 排列，两种条件的安全数均为 36、79、87、100，安全入靶数为 27、52、87、100。只增大滚转惯量至 3 倍或只减滚转力矩至 1/4 时，四者均 100/100 安全入靶。表内滚转力矩随全轴倍率换算，单轴试验不足以认定该值为滚转独立下限。

## 推力、延迟与两条迁移路线

四个推力与延迟条件均保持名义惯量。每格依次列出安全数 / 安全入靶数（满分均为 100），括号内是原始平均回报。

| 条件 | online | bc_only | scripted_nominal | scripted_privileged |
|---|---|---|---|---|
| 25% 限推 | 100/100（93.36） | 100/100（91.93） | 100/100（91.93） | 100/100（92.11） |
| 25% 限推 + 延迟 | 100/100（93.32） | 100/100（91.88） | 100/100（91.85） | 100/100（92.03） |
| 保留全推 | 100/100（90.61） | 0/0（-65.32） | 0/0（-67.88） | 100/100（92.11） |
| 保留全推 + 延迟 | 100/100（90.55） | 0/0（-65.36） | 0/0（-68.99） | 100/100（92.03） |

对 online，单独把推力提高到候选船的全推水平，加入悲观延迟后仍有 100 次安全入靶。源域结果没有显示 25% 限推是它的必要条件。对 bc_only 和 scripted_nominal，全推下的失败均为超时，采用限推可恢复这两个对照的着陆表现。操作方案还取决于姿控能力。相同的全轴惯量 ×2 时，online 在全推与限推下分别为 100/100、98/89（安全/安全入靶）。惯量 ×4 时分别为 88/85、38/28。单改油门不能替代姿控标定。

**路线 A 保留现有飞船的姿控能力。** 若分轴脉冲确认其能力接近弱端点，读到正确物理参数的脚本在该代理条件下仍有 100 次坠毁，安全入靶 0 次，RCS 在 94.7% 的控制步饱和。它在全轴惯量 ×6 时仍有 95 次安全入靶，不能把这一成绩外推到 ×10.71。保留飞船意味着应以实测执行器校准模拟器，重新设计或调节脚本、验证其能安全着陆，再采集克隆示范并重训。行为克隆仍是一种可尝试的热启动方法，当前脚本在这个弱端点无法直接提供安全示范。

**路线 B 提高飞船可用力矩，试跑冻结 v1。** 以 online 在名义推力下最后一个达标网格点为设计参照，候选船俯仰、偏航、滚转对应约 **7.04、6.77、5.24 kN·m**，当时为 98/100 安全、88/100 安全入靶。纯克隆在较低的 4.69、4.51、3.49 kN·m 参照点仍有 97/100 安全，但在全推代理下的表现另见本节。改船需要核对每轴正反向可用力矩，并在构型变化后复测湿质量、惯量和响应。若惯量也变了，应以目标角加速度重新换算力矩。达到源域参照值后可以不更新权重，按事前顺序做 KSP 零样本评估，实际成功率待测。

## 三名零样本候选的稳健性

每项均使用同一验证清单。下表给出 100 次中安全且入靶的次数，便于比较三者的条件依赖性。

| 条件 | online | bc_only | scripted_nominal |
|---|---:|---:|---:|
| 名义条件 | 100 | 100 | 100 |
| 仅惯量 ×4 | 27 | 52 | 87 |
| 弱姿控估计端点（惯量 ×10.71） | 0 | 1 | 0 |
| 仅全推 / 仅 25% 限推 | 100 / 100 | 0 / 100 | 0 / 100 |
| 燃料原样喂入 / 按满箱质量换算 | 0 / 100 | 0 / 100 | 0 / 100 |
| 高度偏差 −0.3 m / +0.3 m | 100 / 100 | 100 / 100 | 100 / 99 |

高度偏差只加在控制器读取的 z 上，真实碰撞平面和任务判定不变。两个冻结学习策略在 ±0.1、±0.3、±0.5 m 六个测试点都为 100/100 安全入靶，但首次触地速度已有变化。例如 z 低报 0.3 m 时，online 平均触地速度从 1.356 增至 1.426 m/s，bc_only 从 0.514 增至 0.858 m/s。名义脚本在高报 0.3、0.5 m 时分别坠毁 1、2 次。实船几何偏置和接触事件仍应单独标定。

## 请适配组补测的量

- 在同一飞船、分级、活跃发动机和燃料量下，导出 kRPC 的 `available_torque`、`available_rcs_torque`、`available_reaction_wheel_torque`、`available_engine_torque`。请保留正反向力矩、轴序、参考系和单位，并附飞船及存档标识、质量、惯量和时间。这样可以将各来源的可用力矩与上表的逐轴需求比较。
- 分别在发动机关闭、接近实测悬停油门时，对俯仰、偏航、滚转各施加正负短脉冲。逐物理帧记录 UT、指令和实际输入、机体系角速度向量、实际推力及脉冲前后的状态。两种油门下同轴响应的差异可帮助区分 RCS 与发动机摆动的贡献，横向速度也可用于量化 RCS 平移耦合。
- 对四台 Terrier 逐台记录 gimbal 是否启用、允许摆角与限制。在适配器当前 `reaction_wheels=False`、`rcs=True` 的实际设置下报告响应和各来源力矩，确认反作用轮的可用读数与实际生效力矩的关系，以及 gimbal 在开机时是否参与姿态控制。[控制器设置](https://github.com/Aurora-on/KSP/blob/01aac917/ksp_env/env.py#L568-L588)

## 燃料观测提案

只改变观测中的燃料量，按候选船 5,000 kg 满箱读数原样输入时，两个冻结学习策略各坠毁 100 次，名义脚本 100 次超时。按满箱比例换算后，三者均恢复 100 次安全入靶，相对名义平均回报的绝对差分别为 3.21×10⁻⁸、5.23×10⁻⁹、1.07×10⁻⁸。

环境按 kg 输出当前主发动机推进剂的总质量，候选船为 LiquidFuel 与 Oxidizer 之和（满箱 5,000 kg）。建议在策略入口按**当前构型满箱主推进剂质量**换算，保留原始 kg 用于动力学、奖励、回放和耗料诊断。旧策略的输入预处理已除以 600 kg，因此用 `rescale_fuel(obs, source_capacity_kg=600, target_capacity_kg=5000)` 将该通道乘以 600/5000，再交给冻结策略。例如实船半箱 2,500 kg 转成 300 个源域 kg，策略最终看到 0.5。将来在 5,000 kg 容量的模拟器上训练时，现有 `scales.fuel = fuel_capacity` 规则直接使用新容量，无需重复缩放。若构型改变，则查该构型的满箱容量。此处提出策略输入约定，共享配置的正式归一化决策仍待团队确认。[策略预处理](../src/mun_agent/interface.py) · [候选实船燃料定义](https://github.com/Aurora-on/KSP/blob/01aac917/docs/nominal-task-decisions.md#L17-L23)

## 适用范围

模拟器采用固定轴向主推力、机体系力矩与平地点接触。它缺乏原生油门延迟、RCS 平移耦合、发动机 gimbal 及 KSP 支腿与地形接触动力学。改变惯量和推力比较的是源域单项与指定组合的敏感性，尚未同时复现整船的质量、耗料、姿态和接触响应。所有学习策略数字只适用于这两个冻结检查点和固定验证清单，测量网格以外的能力以及实际 KSP 零样本着陆率仍待验证。同一组起点上的不同扰动相互配对，12,000 个正式回合来自同一份 100 起点清单的重复使用。[模拟器动力学](../../simulator/src/mun_lander/physics.py) · [接触模型](../../simulator/src/mun_lander/env.py)

## 复现与本地结果

从仓库根目录使用 CPU。在同一 Python 环境安装 `simulator` 和 `agent`。实验代码为 `86465b4`。先比对压缩包 SHA-256 `01e5dad61253d1910e96b343e8d0dbe7719d8b59f8cab7139e10c003983812f9` 和纯克隆检查点 SHA-256 `8fa4ccdf2ebf5bc684200e10ac03d6e7a9e99f97bd342f9b68df977e804778fb`。将发布包解压到 `agent/runs/transfer-sensitivity/bundle/`，保留 `handoff.json`。将纯克隆检查点放在 `agent/runs/s3-stable/seed-33/checkpoints/bc-only.pt`，并准备同批归档的 `agent/runs/s3-stable/report/selection.json` 交叉核对输入。可分别用 `--bc` 和 `--selection` 指定这两份训练端文件。[发布包](https://github.com/Aurora-on/KSP/releases/tag/s3-source-seed33-r22-v1) · [评估脚本](../scripts/transfer_sensitivity.py)

```sh
python agent/scripts/s3_handoff.py verify agent/runs/transfer-sensitivity/bundle
python agent/scripts/transfer_sensitivity.py --workers 9
```

本地 `agent/runs/transfer-sensitivity/` 下的 `summary.md` 和 `summary.json` 给出每个条件和控制器的安全数及 Wilson 区间、入靶数、失败分类、触地速度、回报和 RCS 饱和比例。饱和比例按实际执行动作统计，任一轴绝对值达到 0.99 的步数除以全部控制步数。`pairs/` 留存逐回合记录，`repeat/` 留存复测。正式评估覆盖 32 个条件、120 组控制器与条件组合，共 12,000 回合。名义回报依次复现 93.3988、92.0332、92.1085。对名义、惯量 ×4、原样 kg 三个条件重跑适用的 11 组共 1,100 回合，逐回合记录完全一致。环境为 Python 3.14.4、PyTorch 2.15.0、NumPy 2.5.4。输入摘要和代码版本随结果记录。仓库四项检查通过，包含 Python 编译、根目录 53 项测试（2 跳过）、模拟器 61 通过（1 跳过）、agent 111 通过（1 跳过）。
